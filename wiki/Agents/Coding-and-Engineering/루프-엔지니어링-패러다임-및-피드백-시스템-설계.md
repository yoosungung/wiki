# 🔄 루프 엔지니어링(Loop Engineering) 패러다임 및 자율 에이전트 피드백 시스템 설계

자율 에이전트(예: Claude Code, Zed, Cursor)의 등장으로 AI 엔지니어링의 중심이 단순 지시문을 조율하는 프롬프트 엔지니어링에서 **피드백 제어 루프를 아키텍처화하는 루프 엔지니어링**으로 격상되었습니다.

## 1. 루프 엔지니어링의 4대 구성 요소
1. **트리거 (Trigger)**: 개발자의 특정 동작(코드 수정, 빌드 실패 알림, Linear 티켓 업로드)을 감지하여 자율 작업을 촉발하는 게이트웨이.
2. **작업 스키마/작업 트리 (Worktree & Skills)**: 에이전트가 동작할 셸 명령어, git 명령어, 파일 제어 API 등의 허용 범위와 스킬 정의서(`SKILL.md`).
3. **평가기 (Evaluator)**: 빌드 오류 정적 분석, diagnostics 컴파일 검사기 등 에이전트의 중간 패치가 유효한지 검증하는 지능 레이어.
4. **종료 및 탈출 규칙 (Stop Rules & Hard Limits)**: 무한 루프에 빠져 API 비용(인풋 토큰 폭발)을 허비하는 것을 방지하기 위한 최대 실행 횟수(예: 3회 제한), VRAM/토큰 임계점 및 인간 에스컬레이션 규칙.

## 2. 의의
- 엔지니어는 더 이상 '답변을 생성하기 위해 단발로 설득하는 프롬프트'를 쓰지 않고, 에이전트가 스스로 실수를 수리하고(self-fixing) 목표에 수렴할 수 있는 **지속성 자율 순환 환경**을 조율합니다.
