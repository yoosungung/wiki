# 코딩 에이전트 하네스 엔지니어링 가이드

에이전트 하네스 엔지니어링(Harness Engineering)은 아무리 뛰어난 기초 모델(Foundation Model)이라도 적절한 실행/통제 환경이 주어지지 않으면 실제 개발 태스크에서 실패하기 쉽다는 한계를 극복하기 위해, 모델 주변에 신뢰할 수 있는 개발 환경을 구축하고 이를 정교하게 통제하는 구조입니다.

## 1. 하네스의 필요성
동일한 모델(예: Claude 3.5 Sonnet / Opus 등)이라도 적절한 검증/통제 레이어 없이 실행되었을 때는 컨텍스트 유실, 조기 태스크 종료 선언, 린트/테스트 에러 무시 등의 현상을 겪게 됩니다. 하지만 적합한 하네스(Planner + Generator + Evaluator) 체인 내에서 동작할 때는 성공률과 구현 신뢰도가 비약적으로 향상됩니다.

## 2. 하네스의 5대 핵심 서브시스템
하네스 아키텍처는 다음과 같은 5가지 독립적인 하위 시스템으로 설계됩니다.

1. **Instructions (지침 제어)**
   - 에이전트가 준수해야 하는 최우선 작업 지침서 및 순서를 명문화합니다.
   - 예: `AGENTS.md`, `CLAUDE.md`, 피처 리스트 및 요구사항 명세서.
2. **State (상태 관리)**
   - 에이전트의 다회차 실행 과정(Session)에서 생기는 진척도를 계속 추적합니다.
   - 예: 작업 진척도 기록 파일, 세션 핸드오프용 메모, Git 커밋 및 diff 추적.
3. **Verification (검증 제어)**
   - 에이전트의 작업 결과물을 기계적으로 신뢰할 수 있도록 강제합니다.
   - 예: 유닛 테스트 자동 구동, 코드 린터(Linter) 및 타입 체크(Type check), smoke run.
4. **Scope (범위 통제)**
   - 에이전트가 지나치게 광범위한 파일을 오염시키거나 제어 범위를 이탈하지 않도록 엄격하게 가둡니다.
   - 예: "한 번에 단 하나의 기능만 구현할 것", Definition of Done(완료 기준) 설정.
5. **Session Lifecycle (생명주기 제어)**
   - 세션의 시작부터 끝까지 작업의 영속성(Persistence)을 보장합니다.
   - 예: 시작 시 `init.sh` 구동, 종료 시 깨끗한 환경 청소 체크리스트 실행.

```text
                    THE HARNESS PATTERN
                    ====================

    사용자 --> 작업 지시 --> 에이전트가 하네스 규칙 로드 --> 작업 수행
                                                        |
                                              하네스가 모든 단계 감시:
                                              |
                                              +--> Instructions: 행동 순서와 원칙 강제
                                              +--> Scope:        작업 경계 한정 (오버리치 방지)
                                              +--> State:        진척 상황을 log.md 등에 보존
                                              +--> Verification: 테스트 및 린트 합격 강제
                                              +--> Lifecycle:    안전하게 다음 세션으로 연계
                                              |
                                              v
                                         모든 검증을 완벽히 통과할
                                         때에만 에이전트가 작업을 종료함
```


## 3. 자율 개선 하네스 (Self-Harness)
전통적인 하네스 엔지니어링은 인간 전문가가 수작업으로 지침과 검증 방식을 설계해야 하는 한계가 존재했습니다. 이를 해결하기 위해 에이전트가 스스로의 실행 트레이스를 기반으로 하네스를 직접 개선하고 진화시키는 **Self-Harness** 패러다임이 제안되었습니다.

- **작동 루프**:
  1. **Weakness Mining (실패 분석)**: 에이전트 구동 과정에서 발견되는 반복적인 에러나 약점을 분석합니다.
  2. **Harness Proposal (하네스 제안)**: 탐색된 실패에 최적화된 새로운 하네스 지침이나 검증 룰을 제안합니다.
  3. **Proposal Validation (회귀 테스트)**: 제안된 하네스를 기존 벤치마크 테스트셋에 대조 검증하여 최종 적용 여부를 자율 결정합니다.
- **의의**: 베이스 모델을 고정하더라도 하네스를 실시간 개선함으로써, 복잡도가 높고 빠르게 동적으로 변하는 환경에서 에이전트의 생존 능력을 극대화할 수 있습니다.
