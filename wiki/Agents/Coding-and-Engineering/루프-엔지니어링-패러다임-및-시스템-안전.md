# 루프 엔지니어링(Loop Engineering) 패러다임 및 시스템 안전

인간이 에이전트와 한 턴씩 대화하며 프롬프트를 입력하고 정제하던 기존의 보조 어시스턴트 구조가 가파르게 해체되고 있습니다. 현대 에이전트 아키텍처는 인간의 즉시 개입 없이 에이전트가 스스로 판단하고 행동 루프를 지속 제어하는 **루프 엔지니어링(Loop Engineering)** 패러다임으로 고도화되고 있습니다.
 
## 1. 앤드류 응(Andrew Ng)의 제품 개발 3대 루프
앤드류 응은 AI 에이전트를 사용한 신규 제품(0-to-1) 개발 시 작동하는 상호 순환 구조를 3대 핵심 루프로 정의했습니다.
 
1. **Agentic Coding Loop (에이전틱 코딩 루프)**: 제품 사양(spec)과 평가셋(evals)을 입력받아 에이전트가 코드를 작성, 테스트, 자율 수정하는 빠른 반복 루프(수 분 단위 회전). 인간의 QA 개입 없이 스스로 브라우저 렌더링 검증 등까지 완수하여 약 1시간 이상 긴 시간 자율 운용 가능.
2. **Developer Feedback Loop (개발자 피드백 루프)**: 인간 개발자가 에이전트의 완성물을 감시하고 spec을 다듬거나 evals를 보강하여 에이전트의 방향성을 고수준에서 조정하는 조종(steering) 루프(수십 분~수 시간 단위). 개발자가 단순 디버깅에서 해방되어 핵심 아키텍처 및 비즈니스 베팅에 집중할 수 있게 됨.
3. **Strategic Control Loop (제어 및 앵커링 루프)**: 에이전트들이 상호 검증하는 다중 루프(recursion)는 단독으로 안전하지 않음. 루프가 폭주하여 비용을 낭비하거나 잘못된 결과로 유도되지 않도록, **결정론적 앵커(deterministic anchors)**, **측정 가능한 에러 시그널(error signals)**, **명시적 정지 조건(stop conditions)**을 통제하여 시스템의 전체 수렴(convergence) 신뢰성을 통제하는 루프.
 
## 2. 상태 외부화(State-Externalizing) 하네스 설계
에이전트의 긴 탐색 과정(trajectory)이나 중간 검증 로그가 모델의 컨텍스트 창(Context Window)에 무작위로 계속 쌓이면, LLM의 연산 부담과 판단 주의력 분산으로 인해 루프 전체가 붕괴됩니다.
- **하네스에 상태 위임**: 검색, 문서 선별, 검증 기록, budget control 같은 상태 추적 및 스케줄링은 에이전트 프레임워크/하네스(Harness)가 외부적으로 전담해야 합니다.
- **행동 집중**: LLM은 하네스가 외부화해 둔 간략화된 현재 상태 메타데이터만을 보고 "다음에 무엇을 할지"에 대한 다음 행동 판단에만 몰입하도록 격리하는 것(예: Harness-1 아키텍처)이 성능과 비용 측면에서 압도적으로 유리합니다.
 
## 3. 루프 엔지니어링의 5대 핵심 서브시스템
자율적인 에이전트가 안전하고 영속적으로 가동되기 위해 외곽 시스템은 다음 5대 기능을 확보해야 합니다.
1. **발견 (Discovery)**: 실패한 빌드, 테스트 에러, 새로운 티켓 등을 에이전트가 스스로 검색 및 탐색하여 작업 큐를 형성합니다.
2. **인계 (Handoff)**: 에이전트들이 상호 충돌 없이 독립적으로 코드를 수정할 수 있게 격리된 Copy-on-Write 샌드박스 및 Git 워크트리를 동적 할당합니다.
3. **검증 (Validation)**: 에이전트 특유의 '결과물 자동 미화 및 자기 칭찬 편향'을 해쇄하기 위해, 작업 수행 레이어와 독립된 냉철한 제2의 에이전트(Verifier)를 개입시켜 유닛 검증 및 회귀 테스트를 강제합니다.
4. **지속성 (Persistence)**: 에이전트 컨텍스트 윈도우 한계를 방지하기 위해, 중간 상태와 핵심 기억 메타데이터를 로컬 파일 맵 및 외부 데이터베이스에 영구 보존합니다.
5. **스케줄링 (Scheduling)**: Cron이나 타이머를 통해 주기적으로 에이전트 루프를 기동하여 백그라운드 모니터링을 자율 완성합니다.

## 2. 자율 루프의 4대 시스템 리스크 및 방어 전략
1. **검증 부채 (Verification Debt)**: 인간의 검토 주기가 에이전트의 생성 주기보다 느려져, 시스템 내부에 점진적인 오류 코드가 누적되는 현상. (철저한 정기 린트 및 다층 검증자 검증 필요)
2. **이해의 부패 (Decay of Understanding)**: 코드가 너무 빠르게 자동 누적되어, 전체 시스템의 논리 구조와 아키텍처를 온전히 이해하는 인간 리드가 소멸하는 부작용.
3. **인지적 항복 (Cognitive Surrender)**: 에이전트의 자율 패스가 이어지면서 인간 관리자가 비판적인 감시를 멈추고 제안에 무조건 순응하게 되는 현상.
4. **토큰 폭발 (Token Runaways)**: 무한 루프 제어 실패로 인해 단 몇 시간 만에 과도한 모델 호출 비용이 발생하는 현상. (TUI 대시보드 비용 리미터 및 시간당 호출 한계 강제 필요)

엔지니어의 진짜 가치는 하위 단계 구현이 아닌, 수많은 에이전트가 서로를 상호 검증하고 보호하는 안전 궤도인 **외곽 시스템(하네스) 설계**에 있습니다.
