# 자율수행 멀티 에이전트 시스템(MAS) 오케스트레이션 및 보안 격리 (2026)

2026년 멀티 에이전트 시스템(MAS)은 개별 도구 중심의 한계를 뛰어넘어 ## 1. 군집 지능 및 자율 오케스트레이션 (Swarm Intelligence & Auto-Orchestration)
- **Swarm Intelligence**: 중앙의 정적 통제 없이도 에이전트들이 실시간으로 통신 프로토콜을 사용해 상황 인식을 공유하고, 분산된 과업의 선후 관계 및 의존성을 스스로 협상하여 최선의 경로로 작업을 수행합니다.
- **Goose Framework & Builderbot (Block 주도)**: 
  - **Goose Framework**: 파일 I/O, 코드 실행, 시스템 셸 연동 도구들을 결합하여 실무급 자율 동작을 빌드하는 기업용 오픈소스 에이전트 프레임워크.
  - **Builderbot**: Goose 위에 구축된 대규모 에이전트 오케스트레이터로, 개별 챗봇 형태를 벗어나 전체 코드베이스, Jira/Linear 티켓, CI/CD 파이프라인과 Slack 스레드를 통해 중앙에서 자율 협업 및 조율을 완수합니다.
- **Agentic Engineering Org (에이전틱 엔지니어링 조직)**: 에이전트를 개발 라이프사이클의 1급 객체(First-class Actor)로 지정하여, 인프라 마이그레이션, 장애 자동 복구, 코드 리뷰 등의 작업군을 에이전트 함대(Fleet)가 자율 관리 및 협업하도록 지배(Governance)하는 성숙한 조직 설계론.

## 2. OpenClaw 및 통신 프로토콜 표준화 (MCP & WebMCP)
- **OpenClaw Auto Mode**:
  - 사용자 승인을 건너뛰는 YOLO 모드와 상시 개입 모드 사이에서 **실시간 리스크 스코어링(Risk Scoring, 0-100)**을 수행합니다.
  - 가디언 패턴(Guardian Pattern)을 통해 위협 수준을 감지하고 위험 행동 시 실행 환경, 명령어, 인자가 포함된 **리뷰 패킷(Review Packet)**을 생성하여 정밀 검토를 거칩니다.
- **표준화된 프로토콜 (Model Context Protocol - MCP)**:
  - 에이전트-도구 간 인터페이스는 Anthropic과 Block이 공동 개발한 **MCP**로 표준화되어 외부 데이터와 도구 접근 시 일관성을 확보합니다.
  - 브라우저 제어를 위한 **WebMCP** 표준이 도입되어, 파편화된 DOM 분석 대신 `document.modelContext` 구조화 도구·Permissions Policy `tools`로 인브라우저 자율 동작을 수행한다(Chrome origin trial/flag — [[wiki/Agents/Multi-Agent-and-Orchestration/OpenClaw-및-HyperAgent-기반-MAS-아키텍처.md]]).

## 2. OpenClaw Auto Mode 및 통신 프로토콜 표준화
- **OpenClaw Auto Mode**:
  - 사용자 승인을 건너뛰는 YOLO 모드와 상시 개입 모드 사이에서 **실시간 리스크 스코어링(Risk Scoring, 0-100)**을 수행합니다.
  - 가디언 패턴(Guardian Pattern)을 통해 위협 수준을 감지하고, 허용 정책을 초과하는 위험 행동 시 실행 환경, 명령어, 인자가 포함된 **리뷰 패킷(Review Packet)**을 생성하여 상위 Auto-Reviewer 에이전트의 정밀 보안 검토를 거칩니다.
- **표준화된 프로토콜**:
  - 에이전트-도구 간 인터페이스는 MCP(Model Context Protocol)로 대통합되었으며, 에이전트-에이전트(A2A) 교환 통신 프로토콜 규격을 적용하여 벤더 중립적인 메시지 전송 및 태스크 이관(Hand-off)이 보장됩니다.
  - 브라우저 기능 연동을 위해 **WebMCP** 표준이 도입되어, 파편화된 DOM 태그 분석에 따른 실패율을 배제하고 구조화된 입력값만으로도 웹 상의 자율 동작을 완수합니다.

## 2.1 OpenClaw Workboard (v2026.6.1+) — 2026-07-24 업데이트

단일 게이트웨이 내 공식 오케스트레이션 레이어인 **Workboard**가 Kanban형 카드·의존성 추적을 제공합니다. ([clawdocs multi-agent](https://clawdocs.org/guides/multi-agent))

| 버전 | 기능 | 영향 |
| :--- | :--- | :--- |
| v2026.4.19 | Per-session nested agent scoping | 장시간 에이전트가 다른 세션을 막지 않음 |
| v2026.5.22 | Scoped sub-agent bootstrap | 서브에이전트는 기본 `AGENTS.md`+`TOOLS.md`만 (토큰 절감) |
| **v2026.6.1** | **Workboard primitives** | 의존성 추적형 Kanban 조율 |
| **v2026.6.1** | **Internal namespaces** | 도구 디스패치용 agent/global 세션 격리 |

**카드 수명주기**: `todo → running → review → done` (의존 대기 시 `blocked`).

**에이전트 도구**: `workboard_list|read|create|claim|link|heartbeat|runs|dispatch|reassign|promote`.

```bash
openclaw workboard create --title "Research competitor pricing" \
  --assign researcher --parent card-001
openclaw workboard claim card-002
openclaw workboard update card-002 --status done
```

**디스패치 사이클**: 의존성 준비된 자식 promote → 만료 claim block → 다음 카드 claim → worker 기동 → 완료 추적.

**적용 팁**: 2–3 에이전트는 channel bindings로 충분하고, 태스크 조율이 필요하면 Workboard를 추가한다. 5+ 에이전트·멀티 게이트웨이는 ClawTeam/Mission Control. KM 야간 리서치처럼 Lead→Researcher→Writer 파이프라인은 `workboard_link`로 research→write 의존성을 걸면 된다.

```text
# Gateway exec: ask=off + askFallback=deny
```

4. **[#114152](https://github.com/openclaw/openclaw/pull/114152)** — Control UI ClawHub 검색/상세에 skill 아이콘(origin content-addressed URL만 허용, fallback=publisher avatar). clawhub#3269 의존.

**적용 팁**: Workboard/대시보드 공유는 `/dashboard/...` path를 쓰고, Claude 구독 계정은 discovery가 Bearer로 사는지 한 번 확인한다. 게이트웨이 롤링 재시작 후 “다시 보내 주세요” 메시지가 줄었는지 회귀한다.

## 2.4 OpenClaw route bindings · grep naming · GPT harness (2026-07-27)

당일 main에 게이트웨이 라우트 격리·에이전트 네이밍 규칙·코딩 하네스 경량화가 들어왔습니다.

2. **Grep-discoverability naming** ([`1755087b`](https://github.com/openclaw/openclaw/commit/1755087b)): `AGENTS.md` — export는 2–3단어 고유명; `get`/`run`/`create`/`handle` 단일 단어 금지; 신규 `utils/`·`helpers/`·`common/` 금지; 개념 철자 단일화.
3. **GPT-5.6 coding harness 오버헤드 감소** ([#114574](https://github.com/openclaw/openclaw/pull/114574)): Codex dynamic-tool/provider-capabilities·native apply-patch QA parity·code mode catalog 압축.

```text
# 라우트 바인딩: 공유 dedupe와 분리된 context WeakMap
# aliases ≤ DEDUPE_MAX*4, retainUntilSettled는 바인딩 엔트리 전용
# AGENTS.md: Prefer resolveMessageRouteBinding over get/run/handle
```

**적용 팁**: 멀티 계정 Slack/Telegram 게이트웨이에서 재시도·캐시 hit가 계정 기본값 변경 후에도 같은 라우트를 쓰는지 회귀한다. 신규 코어 모듈은 `utils/` 대신 개념 디렉터리로 두고 export 이름을 grep 가능하게 짓는다. Codex 코딩 에이전트는 #114574 이후 prompt-cache/catalog 토큰이 줄었는지 `openclaw gateway usage-cost`로 확인한다.

## 2.5 OpenClaw watched-session · sandbox browser network (2026-07-28)

1. **Watched-session awareness** ([#114835](https://github.com/openclaw/openclaw/pull/114835)): main 세션의 ambient watched group/topic(`tree` carve-out)을 모델에 명시 — `sessions_spawn`/`sessions_list`/`tree` deny 카피와 시스템 프롬프트가 “못 본다”고 거짓말하지 않도록 수정. 현장 증상: 에이전트가 이미 읽을 수 있는 그룹 히스토리를 부인.
2. **Sandbox browser `network: none` 거부·마이그레이션** ([#115250](https://github.com/openclaw/openclaw/pull/115250)): Docker `network=none`이면 CDP publish 포트가 안 열려 기동 실패. 런타임이 사전 reject; `openclaw doctor --fix`가 기본/에이전트/레거시 roster를 고쳐 `openclaw-sandbox-browser` 네트워크로 복구(침묵 egress 부여 금지).
3. **동일일 보조**: source reply→run session 바인딩(#115434), warm turn 준비 가속(#113817), web·terminal 세션 상태 공유(#115429), startup log shard hang 방지(#115428), plugin install 사전 검증(#115427).

```bash
# network=none 사이드카 정리
openclaw doctor --fix
# watched tree: main 세션에서 sessions_list / 그룹 질의 전 시스템 프롬프트에 watched 목록이 있는지 확인
```

**적용 팁**: 멀티 에이전트 게이트웨이에서 “그룹에서 뭐 했지?” 질문에 대한 부인 회귀를 #114835 이후 확인한다. 브라우저 샌드박스는 `doctor --fix` 후 CDP 포트·허용 egress만 남는지 점검한다.

## 2.8 OpenClaw root-owned plugin bundle (2026-08-01)

1. **Root-owned bundle + scoped registry** ([#117587](https://github.com/openclaw/openclaw/pull/117587) / [`6c9b388`](https://github.com/openclaw/openclaw/commit/6c9b388)): 플러그인 번들을 root-owned 경로에 설치할 때 **scoped registry handles**로 레지스트리 상태를 격리 — 멀티 에이전트/멀티 테넌트 게이트웨이에서 install이 공유 mutable registry를 오염시키지 않음.
2. **선행 패턴**: root-owned bundled runtime deps 지원 (`a99490f`, 2026-04-22).

```bash
# 게이트웨이 플러그인 설치 회귀
openclaw plugins install <bundle>
# root-owned 경로: 에이전트 A install 후 에이전트 B registry handle이 독립인지 확인 (#117587)
```

```text
# 회귀 체크

2. 토큰 갱신만으로 plugin registry rebuild 로그가 폭주하지 않음
```

| 항목 | 재사용 claim |
| :--- | :--- |
| **수명주기** | create→provision→work→**snapshot**→cleanup/restore. SQLite registry + gateway `worktrees.*`(`operator.admin` 변이) |

**적용 팁**: 병렬 에이전트 충돌·임시 checkout 누수를 막으려면 managed worktree를 기본으로 두고, busy 호스트는 `maxCount`/`maxTotalSizeGb`를 켠다. 샌드박스 이미지 업데이트 뒤에는 idle prune(기본 24h)만 기다리지 말고 `sandbox recreate`로 강제 재생성한다.

## 2.15 OpenClaw Task Flow + `tools.exec.mode` (합성 2026-08-22)

정본: [Task flow docs](https://docs.openclaw.ai/automation/taskflow.md). background task 위의 **내구성 멀티스텝 오케스트레이션** 레이어. Gateway 재시작 후에도 flow 상태·revision·자식 task 링크가 남는다.

| 축 | 재사용 claim |
| :--- | :--- |
| **Managed flow** | 플러그인 컨트롤러가 goal + controller id로 생성. 스텝마다 child task; 상태 JSON + **expected revision**(stale write → conflict) |
| **Mirrored flow** | detached ACP/subagent spawn 시 자동 1-task mirror(`task_mirrored`) — 컨트롤러 없이 status/retry 핸들 |
| **Cancel** | `openclaw tasks flow cancel` — sticky cancel, 신규 managed child 거부, 재시작 후에도 유지 |
| **저장소** | `~/.openclaw/state/openclaw.sqlite` (`flow_runs`); legacy `flows/registry.sqlite`는 `openclaw doctor`가 import |
| **스케줄 패턴** | Automations(타이밍) → persistent session(히스토리) → Lobster(결정적 스텝/승인) → Task Flow(멀티스텝 추적) |
| **`tools.exec.mode`** | `deny` \| `allowlist` \| `ask` \| `auto` \| `full`. `auto` = Guardian/native auto-review. `allow-once`→원샷 승인; `ask`/malformed→인간 승인. `askFallback=full`이어도 auto-review가 인간을 요구하면 **실행하지 않음** ([#70543](https://github.com/openclaw/openclaw/pull/70543)) |
| **`mode` vs `host`** | `tools.exec.host` = 실행 위치(sandbox/gateway/node). `tools.exec.mode` = 승인 정책. 둘을 혼동하지 않음 ([permission-modes](https://docs.openclaw.ai/tools/permission-modes)) |
| **Auto 리뷰 패킷** | policy miss 시 command·argv·cwd·env **key names**·host·parser 분석만 포함. 리뷰어는 **저위험 1회(allow-once)** 만 승인 가능 ([공식 블로그](https://openclaw.ai/blog/safer-than-yolo-auto-mode-for-exec-approvals)) |
| **리뷰어 모델 분리** | `tools.exec.reviewer.model`(예: `openai/gpt-5.5`) — 에이전트는 로컬, 호스트 exec 리뷰만 프론티어 가능 |
| **승인 채널** | allow-once / allow-always / deny. allow-once는 plan·cwd·argv·session에 바인딩(승인 후 명령 변경 → reject). Slack·Telegram·iMessage로 라우팅 가능 |

```bash
openclaw tasks flow list [--status <status>] [--json]
openclaw tasks flow show <lookup> [--json]
openclaw tasks flow cancel <lookup>
# audit / maintenance가 stale·stuck cancel·terminal prune(7일)도 담당

# Auto Mode (opt-in; 기본값 유지 — YOLO/full 과 혼동 금지)
openclaw config set tools.exec.host gateway
openclaw config set tools.exec.mode auto
openclaw config set tools.exec.reviewer.model openai/gpt-5.5   # optional
```

**적용 팁**: 단발 배경 잡은 plain task, 플러그인 파이프라인은 managed flow, subagent fan-out는 mirrored flow 핸들로 추적한다. 셸 자동 실행은 `tools.exec.mode: "auto"`로 통일하고, YOLO(`full`)와 혼동하지 않는다. 호스트가 always-ask/deny면 auto도 그 정책을 덮어쓰지 않는다. 리뷰 패킷의 명령·메타데이터는 **untrusted** — 프롬프트 인젝션 시도 시 인간으로 폴백.

## 2.16 OpenClaw 샌드박스 다중 백엔드 격리 및 GuardClaw Judge (합성 2026-09-03)

정본: [OpenClaw Sandbox](https://docs.openclaw.ai/tools/sandboxing) 및 [GuardClaw](https://github.com/guardclaw/guardclaw). 에이전트의 도구 실행 피해 반경(Blast Radius)을 원천 통제하기 위한 다중 백엔드 샌드박스와 런타임 보안 판정(Judge) 계층.

| 축 | 재사용 claim |
| :--- | :--- |
| **샌드박스 모드** | `off`(호스트 직접 실행) \| `non-main`(메인 세션 외 서브에이전트/백그라운드 격리) \| `all`(모든 세션 강제 샌드박싱). 멀티 에이전트 fan-out 환경에서는 `non-main` 또는 `all` 권장 |

| **설정 보호 (Read-Only)** | `~/.openclaw` 디렉터리는 샌드박스 내부에 **엄격한 Read-Only**로 바인드 마운트. 에이전트가 런타임 중 자격 증명 탈취·설정 변조·임의 플러그인 무단 주입을 시도해도 원천 차단 |
| **샌드박스 CLI** | `openclaw sandbox list` (상태 점검) · `openclaw sandbox recreate [--all]` (안전 재생성) · `openclaw sandbox explain` (격리 정책/마운트 검증) |
| **GuardClaw Judge** | 에이전트-도구 사이에 위치하는 보안 판정 미들웨어. 실시간 리스크 스코어링(0–100) 기반 `auto`(위험 행동 차단/인간 승인 요구) vs `monitor`(패시브 감사) 모드 제공 |
| **세션 단위 궤적 추적** | 단일 명령어 검증에 그치지 않고 다단계 세션 전체의 궤적(Trajectory)을 종합 분석하여 개별 무해 명령어가 조합된 다단계 공격 패턴(Multi-step threat) 탐지 |
| **암호학적 실행 원장** | 변조 방지(Tamper-evident) 암호학적 서명 원장을 통해 다중 에이전트 작업 히스토리를 기록하여 오프라인 검증 및 감사 가능 |

```bash

```

**적용 팁**: 멀티 에이전트 협업 환경에서는 `sandbox.mode: "non-main"`을 기본값으로 설정하여 불특정 서브에이전트의 로컬 탈출을 막는다. `~/.openclaw`의 Read-Only 마운트로 인해 플러그인 런타임 설치가 실패할 수 있으므로, 필수 플러그인은 컨테이너 기동 전 호스트에서 사전 프로비저닝해야 한다. 호스트 셸 실행은 GuardClaw 또는 OpenClaw Auto Mode의 리스크 스코어링과 암호학적 서명 원장을 연동하여 오프라인 감사 가능성을 유지한다.

## 3. 샌드박스 격리 아키텍처 (Sandbox Isolation)
에이전트가 자율적으로 셸 명령어를 구동하거나 외부 API를 인보크할 때 발생할 수 있는 보안 균열을 원천 차단하기 위한 시스템 격리 기법입니다.
- **Seatbelt & Bubblewrap Primitives**: macOS의 sandbox profile(Seatbelt) 및 Linux의 namespace 격리(Bubblewrap) 기법을 프로세스 단위에 결합하여 가볍고 견고한 커널 수준의 보안 경계를 형성합니다.
- **Per-Tool Isolation**: 모든 도구 실행 시점마다 마이크로 VM 또는 독립 컨테이너를 일시 가동하는 **도구 단위 일회성 격리(Per-Tool Isolation)**를 구현했습니다. 이로 인해 임의의 도구 오동작 및 악성 스크립트 실행 사고가 메인 에이전트 시스템이나 호스트 OS 환경으로 복제/확산되는 것을 차단합니다.
- **OpenClaw 다중 백엔드 샌드박스 (2026-09-03)**: Docker, Podman, SSH, OpenShell 백엔드를 지원하며, `sandbox.mode`(off/non-main/all)와 `~/.openclaw` Read-Only 격리를 통해 런타임 설정 변조 및 자격 증명 침해를 방지합니다.
- **Exec deny-before-approval (2026-07-25)**: 셸 확장으로 실행 플랜을 고정할 수 없으면 승인 큐에 넣지 않고 deny fallback을 즉시 적용합니다(#113892).
