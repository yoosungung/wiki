# 자율수행 멀티 에이전트 시스템(MAS) 오케스트레이션 및 보안 격리 (2026)

2026년 멀티 에이전트 시스템(MAS)은 개별 도구 중심의 한계를 뛰어넘어 군집 지능(Swarm Intelligence) 및 자율적 스케줄링(Auto-Orchestration)을 특징으로 하는 유기적인 협업 플랫폼으로 안착했습니다. 에이전트의 높은 권한 행사로 인한 보안 위협을 막기 위해 샌드박스 보안 격리가 핵심 인프라로 결합되었습니다.

## 1. 군집 지능 및 자율 오케스트레이션 (Swarm Intelligence & Auto-Orchestration)
- **Swarm Intelligence**: 중앙의 정적 통제 없이도 에이전트들이 실시간으로 통신 프로토콜을 사용해 상황 인식을 공유하고, 분산된 과업의 선후 관계 및 의존성을 스스로 협상하여 최선의 경로로 작업을 수행합니다.
- **Auto-Orchestration**: 상위 오케스트레이터 에이전트가 목표(Goal)를 분석하여 단계별 하위 태스크(Subtasks)로 분해합니다. 이후 작업 큐와 모델의 상황에 맞추어 적절한 최적의 하위 에이전트(Worker)에게 동적으로 분배하고 검증합니다.

## 2. OpenClaw Auto Mode 및 통신 프로토콜 표준화
- **OpenClaw Auto Mode**:
  - 사용자 승인을 건너뛰는 YOLO 모드와 상시 개입 모드 사이에서 **실시간 리스크 스코어링(Risk Scoring, 0-100)**을 수행합니다.
  - 가디언 패턴(Guardian Pattern)을 통해 위협 수준을 감지하고, 허용 정책을 초과하는 위험 행동 시 실행 환경, 명령어, 인자가 포함된 **리뷰 패킷(Review Packet)**을 생성하여 상위 Auto-Reviewer 에이전트의 정밀 보안 검토를 거칩니다.
- **표준화된 프로토콜**:
  - 에이전트-도구 간 인터페이스는 MCP(Model Context Protocol)로 대통합되었으며, 에이전트-에이전트(A2A) 교환 통신 프로토콜 규격을 적용하여 벤더 중립적인 메시지 전송 및 태스크 이관(Hand-off)이 보장됩니다.
  - 브라우저 기능 연동을 위해 **WebMCP** 표준이 도입되어, 파편화된 DOM 태그 분석에 따른 실패율을 배제하고 구조화된 입력값만으로도 웹 상의 자율 동작을 완수합니다.

## 2.1 OpenClaw Workboard (v2026.6.1+) — 2026-07-24 업데이트

단일 게이트웨이 내 공식 오케스트레이션 레이어인 **Workboard**가 Kanban형 카드·의존성 추적을 제공합니다. ([clawdocs multi-agent](https://clawdocs.org/guides/multi-agent))

| 버전 | 기능 | 영향 |
| :--- | :--- | :--- |
| v2026.4.19 | Per-session nested agent scoping | 장시간 에이전트가 다른 세션을 막지 않음 |
| v2026.5.22 | Scoped sub-agent bootstrap | 서브에이전트는 기본 `AGENTS.md`+`TOOLS.md`만 (토큰 절감) |
| **v2026.6.1** | **Workboard primitives** | 의존성 추적형 Kanban 조율 |
| **v2026.6.1** | **Internal namespaces** | 도구 디스패치용 agent/global 세션 격리 |

**카드 수명주기**: `todo → running → review → done` (의존 대기 시 `blocked`).

**에이전트 도구**: `workboard_list|read|create|claim|link|heartbeat|runs|dispatch|reassign|promote`.

```bash
openclaw workboard create --title "Research competitor pricing" \
  --assign researcher --parent card-001
openclaw workboard claim card-002
openclaw workboard update card-002 --status done
```

**디스패치 사이클**: 의존성 준비된 자식 promote → 만료 claim block → 다음 카드 claim → worker 기동 → 완료 추적.

**적용 팁**: 2–3 에이전트는 channel bindings로 충분하고, 태스크 조율이 필요하면 Workboard를 추가한다. 5+ 에이전트·멀티 게이트웨이는 ClawTeam/Mission Control. KM 야간 리서치처럼 Lead→Researcher→Writer 파이프라인은 `workboard_link`로 research→write 의존성을 걸면 된다.

**적용 팁**: Workboard/대시보드 공유는 `/dashboard/...` path를 쓰고, Claude 구독 계정은 discovery가 Bearer로 사는지 한 번 확인한다. 게이트웨이 롤링 재시작 후 “다시 보내 주세요” 메시지가 줄었는지 회귀한다.

2. **Grep-discoverability naming** ([`1755087b`](https://github.com/openclaw/openclaw/commit/1755087b)): `AGENTS.md` — export는 2–3단어 고유명; `get`/`run`/`create`/`handle` 단일 단어 금지; 신규 `utils/`·`helpers/`·`common/` 금지; 개념 철자 단일화.
3. **GPT-5.6 coding harness 오버헤드 감소** ([#114574](https://github.com/openclaw/openclaw/pull/114574)): Codex dynamic-tool/provider-capabilities·native apply-patch QA parity·code mode catalog 압축.

```text
# 라우트 바인딩: 공유 dedupe와 분리된 context WeakMap
# aliases ≤ DEDUPE_MAX*4, retainUntilSettled는 바인딩 엔트리 전용
# AGENTS.md: Prefer resolveMessageRouteBinding over get/run/handle
```

**적용 팁**: 멀티 계정 Slack/Telegram 게이트웨이에서 재시도·캐시 hit가 계정 기본값 변경 후에도 같은 라우트를 쓰는지 회귀한다. 신규 코어 모듈은 `utils/` 대신 개념 디렉터리로 두고 export 이름을 grep 가능하게 짓는다. Codex 코딩 에이전트는 #114574 이후 prompt-cache/catalog 토큰이 줄었는지 `openclaw gateway usage-cost`로 확인한다.

## 2.5 OpenClaw watched-session · sandbox browser network (2026-07-28)

1. **Watched-session awareness** ([#114835](https://github.com/openclaw/openclaw/pull/114835)): main 세션의 ambient watched group/topic(`tree` carve-out)을 모델에 명시 — `sessions_spawn`/`sessions_list`/`tree` deny 카피와 시스템 프롬프트가 “못 본다”고 거짓말하지 않도록 수정. 현장 증상: 에이전트가 이미 읽을 수 있는 그룹 히스토리를 부인.
2. **Sandbox browser `network: none` 거부·마이그레이션** ([#115250](https://github.com/openclaw/openclaw/pull/115250)): Docker `network=none`이면 CDP publish 포트가 안 열려 기동 실패. 런타임이 사전 reject; `openclaw doctor --fix`가 기본/에이전트/레거시 roster를 고쳐 `openclaw-sandbox-browser` 네트워크로 복구(침묵 egress 부여 금지).
3. **동일일 보조**: source reply→run session 바인딩(#115434), warm turn 준비 가속(#113817), web·terminal 세션 상태 공유(#115429), startup log shard hang 방지(#115428), plugin install 사전 검증(#115427).

```bash
# network=none 사이드카 정리
openclaw doctor --fix
# watched tree: main 세션에서 sessions_list / 그룹 질의 전 시스템 프롬프트에 watched 목록이 있는지 확인
```

**적용 팁**: 멀티 에이전트 게이트웨이에서 “그룹에서 뭐 했지?” 질문에 대한 부인 회귀를 #114835 이후 확인한다. 브라우저 샌드박스는 `doctor --fix` 후 CDP 포트·허용 egress만 남는지 점검한다.

## 2.8 OpenClaw root-owned plugin bundle (2026-08-01)

```bash
openclaw plugins install <bundle>
# root-owned 경로: 에이전트 A install 후 에이전트 B registry handle이 독립인지 확인 (#117587)
```

**적용 팁**: 공유 Gateway에 플러그인을 올릴 때 root-owned 번들이면 #117587 이후 빌드를 쓰고, 테넌트별 registry scope가 섞이는지 설치 직후 `plugins list`로 검증한다.

## 2.10 OpenClaw gateway health auth · MMS TimeoutError retry (2026-08-03)

1. **Authenticated gateway health** ([#118996](https://github.com/openclaw/openclaw/pull/118996)): 루트 `openclaw health --token`은 **미지원**. Docker 가이드·Compose producer·설치 힌트는 `openclaw gateway health --token`으로 통일. JSON health contract로 Gateway 서비스·CLI 사이드카를 검증.
2. **MMS stalled body → TimeoutError** ([#119002](https://github.com/openclaw/openclaw/pull/119002)): 원격 미디어가 헤더 후 stall이면 본문 idle/overall deadline을 `TimeoutError`로 표기해 #118994 transient retry가 인식. SMS는 SSRF fail-closed veto 후 공유 classifier 적용. classifier는 `plugin-sdk/retry-runtime`에 위치.

```bash
# Docker/Compose 헬스 — 루트 health --token 금지
openclaw gateway health --token "$OPENCLAW_GATEWAY_TOKEN"

# MMS 첨부 유실 회귀: stall 응답이 permanent fail이 아니라 retry되는지 (#119002)
```

**적용 팁**: Compose proof가 health에서 실패하면 #118996 이전 문서의 `openclaw health --token` 잔존을 의심한다. Twilio MMS 첨부가 간헐 누락이면 media timeout이 plain Error로 떨어지는지 확인하고 #119002 이후 빌드로 올린다.

## 2.11 OpenClaw `/tools` inventory for dynamic models (2026-08-04)

[#119306](https://github.com/openclaw/openclaw/pull/119306): dynamic-provider 세션에서 `/tools`가 **prepared runtime model context**를 publish/borrow하기 **전에** tool resolve를 시도 → 임시 inventory failure. 수정: context 준비 후 inventory.

```text
# 회귀
1. dynamic model 세션에서 /tools 가 빈/실패 없이 inventory 반환
2. Beta lane env-var ratchet(OPENCLAW_* 제거분)과 함께 배포
```

**적용 팁**: 멀티 프로바이더 Gateway에서 `/tools` 깜빡임이 보이면 #119306 이전 빌드인지 확인하고, model context warm 전에 inventory를 캐시하지 않는다.

## 2.12 OpenClaw subagent retention · pluginGeneration (2026-08-09)

1. **Subagent archive 시점** ([#121178](https://github.com/openclaw/openclaw/pull/121178)): `archiveAfterMinutes` 타이머를 **등록 시점**이 아니라 **실행 완료(또는 collector completion 확정)** 이후로 옮김. registration은 retention policy를 만들지 않음. restore는 stale deadline을 clear/recompute. sweeper는 live·yielded·completion-delivery 소유 row를 reclaim하지 않음.
2. **Auth refresh ≠ plugin rebuild** ([#121250](https://github.com/openclaw/openclaw/pull/121250)): auth-only model-runtime refresh가 plugin registry/metadata/provider catalog를 재생성하지 않음. lifecycle-owned immutable `pluginGeneration`을 auth/model snapshot 옆에 두고, registry 재빌드는 config·plugin publication만 담당.

```text
# 회귀 체크
1. 장시간/yielded subagent가 archiveAfterMinutes 전에 사라지지 않음
2. 토큰 갱신만으로 plugin registry rebuild 로그가 폭주하지 않음
```

**적용 팁**: “자식 에이전트가 중간에 증발”하면 #121178 이전 빌드(등록 시 archive arm)를 의심한다. Gateway CPU가 auth refresh마다 튀면 #121250의 `pluginGeneration` 분리 적용 여부를 확인한다.

## 3. 샌드박스 격리 아키텍처 (Sandbox Isolation)
에이전트가 자율적으로 셸 명령어를 구동하거나 외부 API를 인보크할 때 발생할 수 있는 보안 균열을 원천 차단하기 위한 시스템 격리 기법입니다.
- **Seatbelt & Bubblewrap Primitives**: macOS의 sandbox profile(Seatbelt) 및 Linux의 namespace 격리(Bubblewrap) 기법을 프로세스 단위에 결합하여 가볍고 견고한 커널 수준의 보안 경계를 형성합니다.
- **Per-Tool Isolation**: 모든 도구 실행 시점마다 마이크로 VM 또는 독립 컨테이너를 일시 가동하는 **도구 단위 일회성 격리(Per-Tool Isolation)**를 구현했습니다. 이로 인해 임의의 도구 오동작 및 악성 스크립트 실행 사고가 메인 에이전트 시스템이나 호스트 OS 환경으로 복제/확산되는 것을 차단합니다.
- **Exec deny-before-approval (2026-07-25)**: 셸 확장으로 실행 플랜을 고정할 수 없으면 승인 큐에 넣지 않고 deny fallback을 즉시 적용합니다(#113892).
