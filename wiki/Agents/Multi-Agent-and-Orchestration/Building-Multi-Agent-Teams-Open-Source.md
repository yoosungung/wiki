# 🤝 오픈소스 기반 다중 에이전트 오케스트레이션 도구 및 트렌드

## 1. 다중 에이전트 관리용 주요 오픈소스
현업에서는 복잡한 워크플로우를 소화하기 위해 단일 거대 LLM 대신, 각각의 임무가 명확한 전문 에이전트들을 동시 실행하고 관리하는 오픈소스 프레임워크가 인기를 얻고 있습니다.

1. **Graft**: Claude 기반 코딩 가속 프레임워크로, 토큰 사용 효율을 대폭 개선하고 다중 에이전트를 저렴하게 구동할 수 있도록 설계된 에이전트 허브.
2. **Agency agents**: 코딩, 글쓰기, 회계, 마케팅 등 16대 직군에 달하는 232개의 전문 서브에이전트 템플릿 세트를 제공하여 신속한 MAS(Multi-Agent System) 구성 지원.
3. **Codebase memory MCP**: 코드베이스를 인덱싱하고 지식 그래프(Knowledge Graph)로 정제해 에이전트들이 코드 맥락을 즉시 파악하게 만들고 토큰 오버헤드를 극적으로 축소하는 MCP 도구.
4. **OpenMontage**: 코딩 에이전트를 영상 미디어 제작 스튜디오처럼 조직하여 기획, 대본, 에셋 배치, 영상 렌더링까지 전 과정을 협업으로 진행할 수 있는 특화 멀티 에이전트 프레임워크.
5. **Orca**: 비대칭 분산 서버 환경에서 복수의 코딩 에이전트를 동시 실행하고, 부하 상태에 따라 비동기 태스크 큐를 기반으로 작업을 자동 분배하는 오케스트레이터.

## 2. Slack CPO가 제언하는 인간-에이전트 협업 5대 운영 원칙
조직 내에 에이전트를 "팀원"으로서 안착시키기 위해 필요한 철학 및 행동 양식입니다.

### 원칙 1: 대화 로그의 지식 자산화
- 단순 질문-답변 메아리 수준의 대화는 지식이 되지 않음.
- 에이전트는 결론만 기록하는 것이 아니라, 의사결정이 발생한 **맥락(왜 그렇게 정했는지에 대한 논리적 연결선)**을 추출하여 중앙 위키 및 지식 허브에 자동으로 합성해야 함.

### 원칙 2: 에이전트는 준비·실행, 판단은 사람 (Handoff Cycle)
- 에이전트는 자료 수집, 초안 작성, 회의 사전 브리핑 등 리소스를 요구하는 업무를 우선 수행함.
- 사람은 최종 '판단'과 '의사결정'을 수행하며 가벼운 승인 이모지 등으로 프로세스를 위임함.

### 원칙 3: 에이전트 존재 이유의 일 명확화
- 목적이 불분명하고 두루뭉술한 가치를 내세우는 에이전트는 과감히 배제(은퇴)해야 함.
- "이 에이전트가 어떤 핵심 KPI나 결과물을 낳는가?"를 한 줄로 정의하여 역할 혼선을 제거함.

### 원칙 4: 공개 채널 우선 기본값 (Public by Default)
- 실패한 실험이나 사소한 질문들도 투명하게 공개 채널에 공유되어야 에이전트와 동료들이 문제의 원천 패턴을 파악하여 학습할 수 있음. 이를 지원하는 조직 문화가 중요함.

### 원칙 5: 시연 중심의 전파 (Show, Don't Tell)
- 탑다운 방식의 전사 의무 도입이 아닌, 하나의 성공적인 파일럿 팀에서 실제 업무 효율 극대화 사례를 데모하여 유기적으로 인접 부서로 번져가게 유도함.
