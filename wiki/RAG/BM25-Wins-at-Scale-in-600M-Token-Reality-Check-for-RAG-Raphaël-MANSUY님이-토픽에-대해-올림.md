# BM25 Wins at Scale in 600M-Token Reality Check for RAG | Raphaël MANSUY님이 토픽에 대해 올림

BM25 Wins at Scale? A 600M‑Token Reality Check for RAG... If you had to bet on one retrieval strategy for a 500K‑document enterprise corpus, would you choose a clever LLM agent… or plain old BM25? A new paper, “BM25 Wins at Scale: A Scaling Study of Retrieval‑Augmented Generation Paradigms” (Wang et al., 2026) tackles a question most of us haven’t measured properly: How do different RAG paradigms behave as the corpus grows 450×? 👉 WHY Most RAG papers compare methods at one corpus size. Real knowledge bases don’t stay small. When they grow, three things matter: - Accuracy - Build cost (offline tokens) - Query cost + latency (online tokens) Without controlling for scale, reader model, judge, and adversarial distractors, we can’t see the true trade‑offs. 👉 WHAT The authors build a controlled 28‑tier “corpus ladder”: - 1,144 → 511,959 documents - 1.7M → 600M tokens - Same 500 questions, same gold evidence and traps - Same reader (Qwen3.6‑27B) and judging protocol - Token‑level metering They compare 4 paradigms: - Lexical (BM25) - Dense retrieval - Graph‑based RAG (HippoRAG 2, MS‑GraphRAG, LightRAG, LinearRAG) - File‑System Agent (LLM exploring raw files with up to 80 tool calls) Key result: no universal winner — there’s a crossover. - At small scale, the File‑System Agent slightly leads. - Around ~10M corpus tokens, BM25 overtakes it. - At 600M tokens, BM25 leads by nearly 20 points. Dense retrieval stays efficient but less accurate. Graph methods hit construction walls before full scale, often requiring billions of build tokens. 👉 HOW (simple analogy) Think of retrieval like finding a book in a massive library. BM25 builds a global index once. When you ask a question, it ranks the whole library in one shot. The File‑System Agent walks shelf by shelf, reasoning as it goes. That works in a small room. In a skyscraper library, it gets expensive. At full scale: - BM25 ≈ 5.8K tokens per query - File‑System Agent up to ~895K tokens per query - Agent accuracy collapses mainly because it fails to discover the right documents Controlled experiment of interest: - Raw agent: 36.9 - Native BM25: 54.8 - Agent + BM25: 69.4 Iteration helps — but only after strong global candidate ranking. Takeaway As corpora grow, global lexical ranking becomes more valuable than sequential exploration. For enterprise‑scale RAG, BM25 is a strong default. If you want agency, layer it on top of ranked retrieval — not instead of it. This paper is a useful reminder: scaling laws apply not just to models, but to retrieval strategies. Sometimes the “simple” method wins — when you actually test it at scale.
