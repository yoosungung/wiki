# You can see which pipeline wrote a table.

## André Lindenberg님의 업데이트

You can see which pipeline wrote a table. You cannot see which agent read it. OpenMetadata, the open-source data catalog, now stores agent and MCP runs as records: the tables read, the columns, the tool calls, the cost. Ask what an agent touched last month and the answer sits next to the tables themselves. Your runtime posts the record. 14.7k stars, Apache-2.0. Read lineage is the part that actually hurts in production. Write lineage tells you what changed, but when an agent gives you a bad answer you need to know what it read. Having tool calls and column reads sit next to the table turns that into a lookup instead of a dig. The open question is whether you can trust the record. If the runtime reports its own runs, an agent that skips the instrumented path just never shows up. Catching it at the gateway is what makes it auditable.[추천](https://www.linkedin.com/signup/cold-join?session_redirect=https%3A%2F%2Fwww%2Elinkedin%2Ecom%2Fposts%2Falindnbrg_aiagents-datagovernance-datalineage-activity-7491195023473053696-yHlh&trk=public_post_comment_like)[

So the agent reads the table, writes its own witness statement, reports its own tool calls — and we call the result auditable. The suspect has become the court stenographer. Nitesh points to the first problem: anything outside the instrumented path becomes invisible. A gateway can catch the read, but even then it only proves which column was touched. It still cannot tell us whether the agent preserved the column’s meaning, respected the authority attached to it, or quietly reconstructed both afterwards. Excellent metadata.
