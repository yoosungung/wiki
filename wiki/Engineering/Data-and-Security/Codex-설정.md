# Codex 설정

(주의) 지금 Codex 설정을 바꾸지 않으면 토큰을 최대 50배 비싸게 씁니다 GPT-5.6 Luna 의 가격이 80% 내려갔습니다. DeepSeek V4 Flash 도 가격을 유지하며 성능이 큰 폭으로 좋아졌어요. 체감하는 성능 차이는 미미하지만 가격이 믿기 어려울 만큼 낮아졌습니다. 이제 무작정 Sol 을 쓰기보다 작업 별로 모델을 나눌 시점입니다. 이 때 무엇을 고려하여 설정하면 좋은지 5가지로 정리했습니다. ❶ 일단 추가 결제 없이 Codex Luna worker 부터 만듭니다 이미 Codex 를 구독하고 있다면 기존 할당량으로 Luna worker 를 돌릴 수 있습니다. 별도 API 충전이 필요 없는 가장 쉬운 방법이에요. 1/ 일단 ~/.codex/agents/ [luna-worker.toml](http://luna-worker.toml/?trk=public_post-text) 파일을 아래와 같이 수정합니다. name = "luna\_worker" description = "Bounded worker for delegated tasks." model = "gpt-5.6-luna" model\_reasoning\_effort = "max" developer\_instructions = """Work only within the delegated scope. Return evidence and validation.""" 2/ 그리고 [AGENTS.md](https://www.linkedin.com/redir/redirect?url=http%3A%2F%2FAGENTS%2Emd&urlhash=jh-H&trk=public_post-text) 에는 호출 기준을 추가합니다. “독립된 큰 작업은 luna\_worker 에게 병렬로 맡긴다. 각 작업의 파일 범위와 기대 결과를 따로 전달한다.” 이렇게 하면 Sol 은 설계와 최종 검토에 집중하고 Luna Max 가 조사와 구현을 가져갑니다. ❷ 사용량이 부족하면 OpenRouter 또는 DeepSeek API 를 연결합니다 여기서부터는 추가 결제가 들어갑니다. 전반적인 성능을 유지하려면 OpenRouter 의 GPT-5.6 Luna Max 를 선택합니다. model = "openai/gpt-5.6-luna" model\_provider = "openrouter" model\_reasoning\_effort = "max" 비용을 더 낮추려면 OpenRouter 의 DeepSeek V4 Flash 0731 Max 를 사용합니다. model = "deepseek/deepseek-v4-flash-0731" model\_provider = "openrouter" model\_reasoning\_effort = "max" ~/.codex/ [config.toml](http://config.toml/?trk=public_post-text) 에는 OpenRouter provider 를 한 번만 추가합니다. \[model\_providers.openrouter\] name = "OpenRouter" base\_url = " [https://lnkd.in/ggnjUbNq](https://www.linkedin.com/redir/redirect?url=https%3A%2F%2Flnkd%2Ein%2FggnjUbNq&urlhash=up30&trk=public_post-text) " env\_key = "OPENROUTER\_API\_KEY" wire\_api = "responses" 이 provider 하나로 Luna Max 와 DeepSeek V4 Flash 0731 Max 를 모두 호출할 수 있습니다. worker 파일마다 model 값만 다르게 지정하면 돼요. 가장 낮은 cache read 비용이 필요하다면 DeepSeek 공식 API 를 연결합니다. model = "deepseek-v4-flash" model\_provider = "deepseek" model\_reasoning\_effort = "max" ❸ 극적으로 성능비를 개선하고 싶다면 추가 결제를 해야합니다 1/ (추천) Codex Luna worker → 추가 결제 없음. 기존 구독 할당량 사용. 2/ OpenRouter Luna Max → 추가 결제 있음. 세 모델 중 성능과 비용의 균형이 가장 좋음. 단, 2주 동안에 한해 비용이 낮음. 3/ OpenRouter DeepSeek V4 Flash 0731 Max → 추가 결제 있음. DeepSeek 를 사용하면서 데이터 처리 조건을 직접 선택할 수 있음. 4/ DeepSeek V4 Flash Max → 추가 결제 있음. 대량 작업 비용이 가장 낮음. 위 4개 중 어느 방식을 선택하더라도, 1) 이 모델은 main 이 아닌 subagent 로 활용하는 것 2) 각 모델에 대해 reasoning effort 는 무조건 max 로 두는 것 을 기억하세요. 전반적인 모델 단가는 낮추되 결과 품질을 최대한 유지하는 것을 원칙으로 생각해야 합니다. ❹ 라우터 서비스에서 provider 를 고를 때 가격만 보면 안 됩니다 대부분의 경우 openrouter 와 공식 프로바이더에서의 가격이 유사합니다. 하지만 cache 비용을 보면 내용이 달라집니다. DeepSeek 공식 가격 대비 여러 OpenRouter endpoint 의 cache read 가격은 10배 비쌉니다. 그리고 사내에서 사용 하는 경우 데이터 처리 지역도 봐야 합니다. OpenRouter 를 사용할 때 중국 외 provider 를 지정하고 fallback 을 꺼야 해요. data\_collection 을 deny 로 두거나 ZDR endpoint 를 고르는 것도 좋습니다. 마지막은 안정성입니다. provider 별 응답 속도와 uptime 그리고 tool calling 성공률이 다르므로 가장 싼 endpoint 만 고르면 오히려 재시도 비용이 늘 수 있습니다. ❺ 결국 선택은 우리에게 달려 있습니다 추가 결제 없이 적용할 수 있는 최선의 선택은 Codex Luna Max. FOMO가 와서 토큰 비용을 끝까지 낮추려면 DeepSeek V4 Flash Max. 전반적인 성능은 GPT-5.6 Luna 가 낫습니다. 하지만 DeepSeek V4 Flash 의 속도와 가격은 대량 subagent 작업의 비용 구조를 근본적으로 바꿀 만큼 강합니다. OpenAI 와 Deepseek 덕분에 우리는 정말 완전히 새로운 시대에 진입했습니다. 이제 Sol 하나로 모든 일을 처리하지 마세요. Sol 이 판단하고 Luna 와 DeepSeek 는 일을 나눠서 처리하게 만드는 것이 지금 가장 비용 효율적인 Codex 설정입니다. 꼭 필요한 AI 정보를 지속적으로 업로드하고 있습니다. 저와 "1촌"이 되면 유용한 정보를 놓치지 않을 거에요.

Codex 에서 Max(최대) 가 안 보이시는 분들은 설정 - 구성 - 모델 기능 - 사용 가능한 추론 수준에서 최대, 울트라를 선택해주세요. 별개로 이 모델명과 관련하여 설명을 간단히 드리자면, 울트라는 서브에이전트 스폰을 최대화 한 오케스트레이션 형 추론 레벨입니다. 최대 까지가 reasoning\_effort 를 최대한 길게 한 test-time scaling 이고요. 여기에 chatgpt 에는 pro 모델이 존재하는데 이 모델은 deep research 입니다.
