# I just rewrote OpenWiki's entire prompt in v0.3 to generate more detailed & accurate wikis. Eval results

- 📈 28.57% success increase (35% to 45% @ n=2)
- 🪙 14% fewer tokens
- 🧰 26% fewer tool…

I just rewrote OpenWiki's entire prompt in v0.3 to generate more detailed & accurate wikis. Eval results: - 📈 28.57% success increase (35% to 45% @ n=2) - 🪙 14% fewer tokens - 🧰 26% fewer tool calls per successful task And as you can clearly see from the graphs, the wikis contain much more data now. Try out the new and improved OpenWiki: [https://lnkd.in/gsRJmSnx](https://www.linkedin.com/redir/redirect?url=https%3A%2F%2Flnkd%2Ein%2FgsRJmSnx&urlhash=HkDr&trk=public_post-text) npm install -g openwiki@0.3.0 That said, initial OpenWiki generation consumes far more tokens (~10-15M from ~2-3M prev) than before, but when running on Luna it's still less than $1/wiki init, with my most expensive run only reaching $7 to generate a wiki for the main LangSmith monorepo (>2.5M LoC) Ran over a subset of tasks from the DeepSWE benchmark: [https://lnkd.in/g6zzzu6F](https://www.linkedin.com/redir/redirect?url=https%3A%2F%2Flnkd%2Ein%2Fg6zzzu6F&urlhash=fwo3&trk=public_post-text)
