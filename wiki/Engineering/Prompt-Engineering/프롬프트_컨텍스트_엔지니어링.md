# 프롬프트 엔지니어링과 컨텍스트 엔지니어링

이 LinkedIn 게시물은 프롬프트 엔지니어링과 컨텍스트 엔지니어링의 개념 및 중요성에 대해 설명합니다.

*   **프롬프트 엔지니어링:** LLM(대규모 언어 모델)의 역할, 규칙, 출력 형식을 정의하고 예시를 통해 원하는 출력을 유도하는 기법입니다. 초기에는 시스템 프롬프트와 소수 예시로 단발성 작업 성능 향상에 집중했습니다.
*   **컨텍스트 엔지니어링:** 모델이 추론에 사용하는 전체 토큰 집합(시스템 지시문, 도구, 외부 데이터, 대화 히스토리 등)을 언제, 무엇을, 얼마나 넣을지 설계하고 관리하는 기법입니다. 프롬프트 엔지니어링의 자연스러운 진화로 제시되며, 목표 행동을 유도하는 최소한의 컴팩트한 컨텍스트를 지속적으로 선별하고 주입하는 것이 핵심입니다.
*   **컨텍스트가 중요한 이유:** 트랜스포머 아키텍처의 특성(어텐션 분산), 컨텍스트 rot(정보 정확도 저하), Lost in the Middle(관련 정보가 중앙에 있을 때 답변 품질 저하) 현상 때문에 효율적인 컨텍스트 주입이 필수적입니다. 불필요한 토큰은 비용과 지연을 증가시키고 오류 가능성을 높입니다.
*   **프롬프트 엔지니어링의 미래:** 단순히 질문을 잘하는 프롬프트의 역할은 축소되고, 컨텍스트, 툴, 메모리, 검색 흐름을 설계하는 상위 운영 설계 역량이 중요해집니다. 프롬프트 자체는 에이전트 운영 규범, 툴 사용, 검색, 요약 규칙 등을 안내하는 핵심적인 "운영 계약서" 역할을 합니다.
*   **에이전트를 위한 프롬프트 엔지니어링 팁:**
    *   **시스템 프롬프트:** 너무 하드코딩하거나 모호하지 않게 Role, Objectives, Constraints, Tools, Output 등으로 섹션화하고, 규칙은 불릿으로, 예시는 2-3개만 넣습니다.
    *   **툴 설계:** 하나의 의도에 하나의 툴을 사용하고 파라미터를 명확히 합니다.
    *   **예시 설계:** 평균 사례 1개, 난이도 상승 사례 1개, 실패 후 수정 사례 1개로 충분하며, 엣지 케이스를 과다하게 나열하지 않습니다.
    *   **컨텍스트 조회 전략:** 런타임 Just-in-Time 검색으로 전환하여 가벼운 식별자만 유지하고 필요할 때 툴로 로드합니다.
