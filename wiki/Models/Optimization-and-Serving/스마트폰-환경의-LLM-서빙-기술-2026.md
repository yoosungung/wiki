# 스마트폰 환경의 LLM 서빙 기술 및 아키텍처 (2026)

2026년 현재 모바일 온디바이스(On-device) LLM 서빙은 실험적 단계를 넘어 프로덕션 표준으로 자리 잡았습니다. 하드웨어 가속기(NPU)의 발전과 효율적인 런타임 프레임워크의 등장이 이를 견인하고 있습니다.

## 1. 주요 모바일 LLM 프레임워크

| 프레임워크 | 주요 특징 | 성능 지표 (iPhone 17 Pro / S26 Ultra) |
| :--- | :--- | :--- |
| **Core AI (Apple)** | **WWDC26 발표. Metal 4 기반 Native Tensor 지원 및 M5/A19 최적화.** | **~60-75 tok/s (Llama 3.3 8B)** |
| **LiteRT-LM (Google)** | Gemma 4 최적화, MTP 지원, **v0.12.0 NPU Delegation. Swift/WebGPU JS API 및 KV Cache 관리.** | **~80-110 tok/s (Gemma 4-E2B Decode w/ MTP)** |
| **ExecuTorch (Meta)** | Llama 4 Scout 최적화. Backend Delegate 가속. | ~45-55 tok/s |
| **Transformers.js v4** | **WebGPU 기본 사용(85% 네이티브 성능), C++ 재작성. 브라우저 내 추론.** | **~60 tok/s (Llama 3.2 3B)** |

## 2. Core AI 집중 분석 (WWDC 2026 업데이트)
2026년 6월 WWDC에서 발표된 **Core AI**는 기존 CoreML을 완전히 대체하는 제너레이티브 AI 전용 추론 프레임워크입니다.

- **아키텍처 혁신**:
    - **Transformer Native**: 어텐션 메커니즘과 트랜스포머 블록에 최적화된 전용 커널(Metal 4)을 탑재하여, 데이터 이동 없는 Zero-copy 추론을 구현했습니다. 특히 **Metal 4는 셰이더 내 Native Tensor 타입을 지원**하여 연산 효율을 극대화했습니다.
    - **Quantized Tensor Formats**: Metal 4는 하드웨어 수준에서 **4-bit 및 2-bit weight 압축**을 기본 지원하여 LLM의 메모리 점유율을 획기적으로 낮췄습니다. (2026-06-17 업데이트)
    - **3계층 추론 시스템**: AFM 3 Core(온디바이스), AFM 3 Advanced(PCC), Global Cloud(Gemini/Claude)를 단일 인터페이스로 오케스트레이션합니다.
    - **coreai-torch**: PyTorch 모델을 중간 단계 없이 직접 Core AI 포맷으로 변환하여 개발 생산성을 획기적으로 높였습니다.

- **성능 (M5 Chip Family 기준)**:
    - **연산 속도**: 소형 모델(Qwen 0.6B 등)에서 MLX 대비 **2.47배 빠른 속도**를 기록했습니다.
    - **Prompt Prefill**: M5 Max 칩에서 20B 규모 모델 기준 **초당 2,500 토큰** 이상의 프롬프트 처리 속도를 달성했습니다.

## 3. LiteRT-LM & Gemma 4 집중 분석 (2026.07 업데이트)
2026년 7월 기준 **Gemma 4** 및 **LiteRT-LM** 업데이트는 온디바이스 AI의 성능과 범용성을 한 단계 격상시켰습니다.

- **LiteRT-LM v0.12.0+ (2026.07.01 업데이트)**: 
    - **네이티브 MTP 오케스트레이션**: Gemma 4 전 제품군(E2B~31B)에 대해 **"Tightly Coupled" MTP Drafter**를 지원합니다. 초경량 **4-layer Drafter 모델**을 사용하여 하드웨어 및 모델 체급에 따라 **2.2배에서 최대 3.0배**의 투기적 디코딩(Speculative Decoding) 속도 향상을 제공합니다. (E2B NPU 기준 **Prefill ~11,000+ tk/s**, Decode ~80-110 tok/s). Gemma 4 E2B 및 E4B 모델 기준 디바이스 성능에 따라 **1.6x ~ 2.2x 추가 성능 가속**이 가능하며, MTP Drafter를 통해 Target 모델의 토큰 예측과 검증 루프를 효과적으로 분리하여 대역폭 제약을 상쇄합니다. (2026-07-08 업데이트) Gemma 4 E2B/E4B 등 경량 모델의 `.litertlm` 형식 온디바이스 패키징 최적화 및 Multi-Token Prediction (MTP) 적용을 통한 모바일 디코딩 가속(최대 2.2x) 세부 스펙 분석 완료.
    - **메모리 로컬리티 최적화**: MTP 구동 시 드래프트 모델과 메인 모델을 동일한 하드웨어 IP(GPU 또는 NPU) 내부 메모리에 로컬 배치하여 IP 간 데이터 전송(Cross-IP Transfer) 오버헤드를 극적으로 방지합니다.
    - **모델 획득**: Pre-converted `.litertlm` 형식 모델은 Hugging Face `litert-community` 조직에서 다운로드하여 오프라인에서 활용할 수 있습니다.
    - **CLI 가동 명령어**:
      ```bash
      litert-lm run \
        --from-huggingface-repo=litert-community/gemma-4-E2B-it-litert-lm \
        gemma-4-E4B-it.litertlm \
        --backend=gpu \
        --enable-speculative-decoding=true \
        --prompt="What is the capital of France?"
      ```
      (사용 환경에 따라 `--backend` 인자를 `npu` 혹은 `cpu`로 스위칭 가능)
    - **교차 플랫폼 NPU Delegation**: 
        - **Android**: Qualcomm QNN, MediaTek NeuroPilot, Google Tensor 통합 API 제공. Qualcomm NPU 기기의 경우 AOT 컴파일을 통해 NPU-ready 페이로드를 생성하며, `QNN_TARGET_BACKEND_HTP` 및 AOT 컴파일 적용을 권장합니다.
        - **macOS/iOS**: Native Swift API 정식 출시. Metal 가속 지원.
        - **Web**: WebGPU 가속 기반 JavaScript API 정식 출시. WebNN을 통한 NPU 직접 접근 지원.
        - **NPU 및 MTP 컴파일 이슈**: Qualcomm QNN/HTP 등 NPU 델리게이트 최적화가 지속적으로 개선되고 있으나, MTP(Multi-Token Prediction) 투기적 디코딩의 복잡한 연산 그래프 컴파일 실패 리스크가 여전히 상존합니다. 따라서 초기 연산 메모리 로컬리티(GPU VRAM 내 드래프트-타겟 모델 동일 배치) 확보와 호환성 측면에서 GPU 델리게이션이 권장되며, 실패 시 XNNPACK CPU로의 폴백 처리가 요구됩니다. (2026-07-07 업데이트)
    - **NPU Delegation 실전 예제**:
      LiteRT-LM API를 사용하여 NPU 가속 및 MTP를 적용하는 파이썬 코드는 다음과 같습니다.
      ```python
      import litert_lm

      # NPU 백엔드를 명시적으로 지정하여 엔진 초기화
      with litert_lm.Engine("path/to/gemma-4.litertlm", backend=litert_lm.Backend.NPU()) as engine:
          with engine.create_conversation() as conversation:
              # 엔진은 MTP 아키텍처가 포함된 모델 패키지일 경우 자동으로 speculative decoding 가속을 활성화함
              for chunk in conversation.send_message_async("온디바이스 가속 기법에 대해 설명해줘"):
                  print(chunk["content"][0]["text"], end="", flush=True)
      ```
    - **저메모리 적용 기법 (Low Memory Techniques)**:
        - **고급 양자화**: INT4 Weight-only (W4A16) 및 Mixed Precision(2/4/8-bit) 지원. KV-cache Quantization(INT8/INT4)을 통해 롱 컨텍스트 처리 시 메모리 사용량을 최대 75% 절감합니다.
        - **Paged KV Cache**: 페이지 기반 동적 메모리 할당으로 메모리 파편화를 방지하고 가용 RAM 사용 효율을 극대화했습니다.
        - **Dynamic LoRA Switching**: 베이스 모델 공유 기반의 실시간 LoRA 어댑터 교체 기능을 통해, 메모리 추가 점유 없이 멀티태스킹이 가능합니다.
        - **Per-Layer Embeddings (PLE)**: 레이어별 임베딩 관리로 초기 모델 로딩 속도와 mmap 효율을 개선했습니다.
    - **상태 관리**: KV Cache 상태 저장 및 복구 기능을 공식 지원하여 긴 대화 세션의 재개 비용을 최소화했습니다.
    - **Constraint Decoding**: `LLGuidance` 라이브러리 통합으로 JSON Schema, Regex, Lark Grammar를 런타임 수준에서 100% 준수 강제.
    - **모델 패키징 및 통합**: 모델 가중치, 토크나이저, 메타데이터가 단일 `.litertlm` 형식 패키지로 통합 구성되어 배포 및 런타임 탑재 과정을 획기적으로 단순화했습니다.
    - **실전 프로덕션 적용**: Chrome 브라우저 내장 AI, Chromebook Plus, Pixel 기기군(Pixel Watch 포함)의 백엔드 온디바이스 추론 엔진으로 활용되어 서비스 연동이 완료되었습니다.

- **Gemma 4 제품군 최적화**:
    - **Gemma 4 라인업**: E2B (2.58GB), E4B (3.65GB), 12B (Medium), 26B MoE & 31B Dense.
    - **iSWA (Interleaved Sparse-Dense Attention)**: 희소 어텐션과 밀집 어텐션을 교차 배치하여 VRAM 사용량을 획기적으로 줄이는 신규 아키텍처를 채택했습니다.
    - **Encoder-free 멀티모달**: Vision/Audio 인코더 없이 LLM 백본에 직접 투영하는 통합 아키텍처로 지연 시간와 메모리 사용량 최소화.
    - **Thinking Mode**: 추론 과정에서 단계별 사고(Chain-of-Thought)를 수행하는 네이티브 모드 탑재.
    - **Gemma 4 31B 실시간 음성 대화 및 Cerebras 추론 가속 (2026.07.05 업데이트)**: Gemma 4 31B 기반 실시간 멀티모달 보이스 앱(Voice App) 오픈소스 스택이 공개되었습니다. OpenAI Realtime API의 드롭인 대체(drop-in replacement) 규격을 만족하며, Cerebras의 초고속 추론 가속(Ultra-fast inference) 백엔드를 연동해 지연 시간이 거의 없는 실시간 음성 응답을 보장합니다. 카메라를 통한 실시간 Vision 이해와 웹 검색(Serper 연동 등)이 가능합니다. 단, "Yes", "No"와 같은 극단적으로 짧은 발화가 누락되지 않도록 최소 VAD(Voice Activity Detection) 튜닝이 요구됩니다. ## 4. 핵심 최적화 기술

### 1) 하드웨어 가속 및 웹 표준
- **WebGPU & WebNN**: WebGPU는 모든 주요 브라우저(Chrome, Edge, Firefox, Safari)에서 디폴트 활성화되어 70% 이상의 지원율을 기록하며, 네이티브 대비 **80~85% 성능**으로 1B~8B 매개변수 모델을 원활히 지원합니다. **WebNN**은 DirectML, CoreML, NNAPI 등 로컬 OS 가속기에 매핑되어 GPU 연산 대비 전력 소모를 획기적으로 줄이는 NPU 직접 접근 게이트웨이 역할을 수행합니다.
- **WebLLM**: OpenAI 호환 API를 온디바이스 상에서 완벽히 제공하는 고성능 브라우저 추론 엔진으로, Llama 3, Phi 3, Gemma 등 최신 모델군을 streaming 및 structured output (JSON mode)과 함께 즉시 적용하는 drop-in replacement 규격을 지원합니다.
- **WebMCP**: 웹 환경 전용 Model Context Protocol (WebMCP)의 등장으로 브라우저 내 에이전트가 웹사이트 상의 기능, 폼, API 도구를 자율 조작할 수 있는 표준 인프라가 확보되었습니다.
- **WASM Memory64 (Wasm 3.0)**: Wasm 3.0은 2025년 9월 W3C 표준 권고안으로 최종 비준되었으며, 2026년 현재 크롬 133+를 비롯해 Safari 등 주요 브라우저 엔진에 완벽히 탑재(Parity 달성)되었습니다. 특히 Memory64 기술을 통해 기존 32비트 주소 공간의 4GB Heap 한계를 16EB(실구현상 **16GB**)로 확장하여, 8B 이상 대형 LLM의 인브라우저 구동을 안정적으로 지원하고 에지 환경에서의 복잡한 AI 연산을 가능케 합니다.
- **모바일 브라우저 메모리 제약 및 캐싱**: 모바일 브라우저 환경에서는 프로세스당 가용 RAM이 대략 **1~4GB** 내외로 강력히 제약되므로 실질적으로 구동 가능한 모델 크기는 양자화된 8B 이하로 엄격히 제한됩니다. 또한, 모바일 사용자 경험과 네트워크 오버헤드를 최적화하기 위해, 모델 가중치 데이터는 브라우저 내부 스토리지인 **IndexedDB**에 로컬 캐싱하여 오프라인에서도 재다운로드 없이 고속으로 가동할 수 있도록 설계하는 것이 2026년 기준 모바일 웹 LLM 서빙의 핵심 전략입니다.
- **NPU 중심 추론 및 신규 엔진**: Apple A19 Pro, Snapdragon 8 Elite 등 최신 NPU를 타겟으로 하며, *wllama*(llama.cpp 기반) 및 *WeInfer* 같은 경량 엔진들이 dispatch 오버헤드를 제어하여 성능 간극을 좁히고 있습니다. TTFT(Time-to-First-Token) 200ms 미만을 달성했습니다.

### 2) 추론 가속 전략
- **투기적 디코딩 (Speculative Decoding)**: 작은 드래프트 모델(예: SmolLM2 135M)이 토큰을 예측하고 큰 모델(예: 3B)이 검증하는 방식으로, 체감 속도를 **1.5~2.0배** 향상시킵니다.
- **Chunked Prefill**: 대규모 입력을 작게 나누어 처리함으로써 초기 응답 시간(TTFT)을 단축하고 앱 반응성을 유지합니다.

## 5. 하이브리드 서빙 모델 (Local-First)
2026년의 주요 앱들은 **Local-First** 전략을 채택합니다.
- **Edge(Local)**: 요약, UI 제어, 개인화 검색 등 전체 작업의 약 80%를 온디바이스 모델(Core AI/ExecuTorch)이 처리합니다.
- **Cloud**: 고도의 추론이나 방대한 지식이 필요한 작업만 클라우드 모델(GPT-5, Claude 4 등)로 에스컬레이션합니다.

## 6. LiteRT-LM 크로스플랫폼 API 확장 (2026-07-11 PM 업데이트)

Google AI Edge는 LiteRT-LM에 **Swift, JavaScript, Flutter API**를 추가하여 Android/iOS/Web/Desktop/IoT에서 동일 오케스트레이션 파이프라인을 제공합니다. Gemma-4-E2B는 Samsung S26 Ultra GPU 기준 Prefill **3,808 tk/s**, Decode **52 tk/s**, TTFT **0.3s**를 기록합니다.

Intel OpenVino NPU 경로에서는 **Gemma4-2B**가 Panther Lake/Lunar Lake용 `.litertlm` 사전 컴파일 번들(4096 context, ~2.95GB)로 배포됩니다.

```bash
litert_lm run --model=gemma-4-e2b --backend=gpu --enable_mtp=true
```

## 6.1 MTP 태스크별 권장 및 Kotlin API (2026-07-12 업데이트)

공식 가이드: MTP는 **GPU 백엔드에서 전 태스크 권장**. CPU에서는 **E4B는 전 태스크 권장**, **E2B는 rewrite/summarize/coding에 선택 적용**(freeform/generative는 오히려 느려질 수 있음).

S26 Ultra GPU 기준 HF 벤치(E2B): Baseline **51.5** tok/s → Summarize MTP **91.7**, Code **84.4**, Rewrite **87.4**, Freeform **66.5**.

```kotlin
val useMtp = backend == Backend.GPU() // CPU E2B freeform에서는 false 권장
val options = LlmInferenceOptions.builder()
    .setModelPath(modelPath)
    .setMaxTokens(512)
    .setUseMtp(useMtp)
    .setTopK(40)
    .setTemperature(0.8f)
    .build()
```

NPU는 Android에서만 정식(✅), Windows는 experimental(🚀). 드라이버 단편화로 `Backend.NPU()` 초기화가 SIGKILL/SIGSEGV를 유발할 수 있으므로 **실험 토글 + GPU→CPU 폴백**을 기본으로 둔다.

E4B 공식 GPU 디코드(참고): S26 Ultra **22**, iPhone 17 Pro **25**, M4 Max **101** tok/s. ([Gemma 4 model card](https://developers.google.com/edge/litert-lm/models/gemma-4))

## 6.2 Swift / `@litert-lm/core` / Session Restore (2026-07-13 PM)

[Google Developers Blog (2026-05-19)](https://developers.googleblog.com/blazing-fast-on-device-genai-with-litert-lm/) 및 [API Overview](https://developers.google.com/edge/litert-lm/api_overview) 기준 실천 포인트:

| SDK | 설치 | 비고 |
| :--- | :--- | :--- |
| **Swift** | SPM `https://github.com/google-ai-edge/LiteRT-LM` from `0.12.0` | Metal, Tool protocol + `@ToolParam` |
| **JavaScript** | `npm i @litert-lm/core` 또는 jsDelivr ESM | WebGPU 기본, 별도 백엔드 설정 불필요 |
| **Flutter** | community `flutter_gemma` | 크로스플랫폼 앱 |

```js
import { Engine } from '@litert-lm/core';
const engine = await Engine.create({ modelPath: '/models/gemma-4-e2b.litertlm' });
const conversation = await engine.createConversation();
const response = await conversation.sendMessage('요약해줘');
```

- **Web 디코드**: MacBook Pro M4 Max WebGPU에서 Gemma 4 E2B ~**76 tok/s** (MTP off 보고치).
- **Session save/restore**: KV cache 직렬화로 재방문 시 heavy prefill 생략 → AI Edge Gallery Agent Skills의 장시간 세션 연속성에 사용.
- **MTP 메모리 로컬리티**: drafter+target을 동일 IP(GPU)에 고정해 cross-IP 전송을 제거하는 것이 2.2x 가속의 전제.
- **Windows 네이티브 CLI (v0.11.0, 2026-05-07)**: LiteRT-LM CLI가 Windows에서 **CPU·GPU 백엔드 모두 네이티브 실행**을 정식 지원하기 시작했습니다(데스크톱 실험·프로토타이핑 경로 확대). 같은 릴리스에서 Gemma 4 MTP가 정식 탑재되었습니다. ([v0.11.0 릴리스](https://github.com/google-ai-edge/LiteRT-LM/releases/tag/v0.11.0))

### LiteRT-LM v0.14.0 — Android CLI/Python · Tool Calling · Auto-Backend (2026-07-16 업데이트)

[v0.14.0](https://github.com/google-ai-edge/LiteRT-LM/releases/tag/v0.14.0)(2026-07-08)은 온디바이스 에이전트 실험 경로를 크게 넓혔습니다.

1. **Android에서 CLI·Python 직접 실행**: `aarch64`/`x86_64`에서 Termux 또는 BeeWare 패키징으로 `litert-lm` CLI·Python API 사용 가능. ([CLI](https://developers.google.com/edge/litert-lm/cli), [Python](https://developers.google.com/edge/litert-lm/python))
2. **Tool calling 스트리밍**: C/Swift API에서 tool-call 토큰 실시간 스트리밍, `LiteRT-LM.js` 전체 tool calling, reasoning/thinking 채널 지원 → 브라우저·네이티브 공통 에이전트 루프 설계 가능.
3. **멀티모달 자동 백엔드**: CLI `run`/`serve`가 audio·vision 모델에 대해 백엔드를 자동 선택하고, **NPU·GPU audio 가속**을 제공.

```bash
# Android(Termux 등)에서 Gemma 4 E2B 빠른 스모크
litert-lm run \
  --from-huggingface-repo=litert-community/gemma-4-E2B-it-litert-lm \
  gemma-4-E2B-it.litertlm \
  --prompt="Summarize on-device tool calling"
# audio/vision은 백엔드 자동 선택; 필요 시 --backend=npu|gpu|cpu 고정
```

구현 팁: Android NPU는 `TF_LITE_AUX`(QNN 페이로드) 부재 시 SIGKILL/SIGSEGV가 날 수 있으므로 **NPU 시도 → GPU(OpenCL/MLDrift) → CPU(XNNPACK)** 폴백을 앱 레이어에 고정한다.

## 6.3 Google AI Edge Gallery & WASM 3.0 완결 (2026-07-14 업데이트)

- **레퍼런스 앱 쇼케이스**: Google AI Edge Gallery 모바일 레퍼런스 앱이 Android 및 iOS 공식 배포 가이드로 자리 잡았습니다. 로컬 Gemma 4 모델(E2B, E4B)을 탑재하여 오프라인에서 음성 대화, 도구 호출(Tool Calling), 멀티모달(Vision/Audio) 연산을 수행하는 구조를 시연하며, Speculative Decoding(MTP) 및 NPU 델리게이션을 통한 최대 2.2배 성능 향상 실사례를 제공합니다.
