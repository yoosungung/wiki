# ⚙️ 에이전트 서빙 병목 분석과 최적화 (AgentSysBench 기반)

## 1. 서빙 병목의 실체: 비-LLM 레이어 (Non-LLM Latency)
Alibaba와 ByteDance가 프로덕션 에이전트 가동 내역을 바탕으로 연구한 **AgentSysBench** 벤치마크 결과에 따르면, 전체 실시간 에이전트 가동 시간 지연 및 리소스 소비의 **절반 이상(50%+)이 LLM 추론 토큰 생성이 아닌 외부 인프라 레이어**에서 발생합니다.
- **자원 과소비**: 하나의 긴 에이전트 대화 세션을 지속적으로 구동 및 보존하는 과정에서 세션당 평균 메모리 사용량이 최대 **28GB**에 이름.
- **지연 편차**: 격리 컨테이너 구동, 도구 응답 대기 및 상태 동기화 처리의 비효율로 인해 서빙 배포 방식에 따라 최대 **32배(32y)**의 TTFT 및 세션 지연 편차가 초래됨.

## 2. 3대 핵심 인프라 최적화 방법론

### 1) Task-aware Serving (태스크 인지형 스케줄링)
- **메커니즘**: 에이전트가 도구를 호출하고(Tool call), 그 응답을 대기하며, 다음 루프를 처리할 때의 상태 흐름을 추론 엔진이 미리 인지하여 전 단계 메모리와 스케줄을 선제 할당(Pre-allocation)하는 방식.
- **결과**: 전체 세션 완료 지연(Latency) 시간을 29% ~ 40% 단축.

### 2) Placement Virtualization (배치 위치 가상화)
- **메커니즘**: 에이전트 인스턴스와 도구가 동작하는 샌드박스 환경 간의 거리를 없애고 가상화 레이어에서 격리 연산을 밀착시키는 기법.
- **결과**: 샌드박스 가상네트워크 왕복 비용 제거를 통해 지연성 **4.5배(4.5x)** 개선.

### 3) State Offloading (상태 외부 오프로딩)
- **메커니즘**: 추론 엔진 코어 메모리에 에이전트 상태(세션 컨텍스트, 도구 응답 결과, 이전 차례 프롬프트 캐시 등)를 무겁게 계속 쥐고 있는 대신, 비동기 고속 메모리 캐시 저장소(외부 스토리지 엔진)로 즉시 오프로딩하여 GPU/서버 호스트 메모리 누수를 전면 차단.
- **결과**: 메모리 상주량 안정화 및 상태 회수 속도 **4.6배(4.6x)** 개선.

### 4) Tool Call Caching (도구 호출 캐싱)
- 에이전트가 수집용 웹 검색, DB 메타데이터 질의 등 동일한 성격의 도구 호출을 중복 반복하는 경향을 분석하여, **결과 캐시 레이어**를 구축함으로써 불필요한 도구 호출의 30% 이상(1/3 상당)을 제거하고 전체 연산 오버헤드를 현격하게 절감함.
