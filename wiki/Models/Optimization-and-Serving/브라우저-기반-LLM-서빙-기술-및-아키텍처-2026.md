# 🌐 브라우저 기반 LLM 서빙 기술 및 아키텍처 (2026)

2026년 현재, WebGPU와 WebAssembly(Wasm)를 활용한 브라우저 내 LLM 추론 기술은 로컬 퍼스트 AI(Local-first AI)의 핵심 표준으로 자리 잡았습니다.

## 1. 핵심 기술 스택 (2026.08 업데이트)

### WebAssembly 3.0 & Memory64 (2026-08-27 정정)
- **4GB 제한 돌파 (Memory64)**: Chrome/Edge **133+**, Firefox **134+**에서 Memory64 지원. JS API 상한은 보통 **16GB**. **Safari / iOS Safari는 미지원**(caniuse 2026-08 — Baseline 차단 요인).
- **성능 함정**: Memory64는 매 접근 bounds check → wasm32 대비 **10%~100% 느릴 수 있음**. >4GB가 필요할 때만 켠다 ([SpiderMonkey](https://spidermonkey.dev/blog/2025/01/15/is-memory64-actually-worth-using.html)).
- **wllama64**: Wllama 포크가 기본 선형 메모리를 **4→16 GiB**로 올림. Chromium **137+** Memory64 경로, 미지원 브라우저는 wasm32 compat(4 GiB). WebGPU·멀티모달·tool calling 유지 ([repo](https://github.com/actuallymentor/wllama64)).
- **WASM 3.0 표준화**: 멀티 스레딩 및 WasmGC 포함. JSPI는 Safari 지연이 남음 — [[wiki/Models/Optimization-and-Serving/WebAssembly-WASM-for-AI.md]].

### WebGPU & WebNN (2026.06.11 업데이트)
- **WebGPU Compatibility Mode**: OpenGL ES 3.1+ 하드웨어에서도 WebGPU를 실행할 수 있게 되어, 전 세계 모바일 기기의 **85% 이상**을 지원하게 되었습니다.
- **WebNN (NPU 가속)**: W3C **Candidate Recommendation** 단계 진입. **MLTensor API**를 통해 WebGPU와 WebNN 간 zero-copy 버퍼 공유가 가능해져 데이터 이동 병목을 제거했습니다.

## 2. 주요 프레임워크 및 최적화

- **Transformers.js v4 (2026.02/06 업데이트)**: C++ 기반 ONNX Runtime 런타임 전면 채택. 2026년 6월 벤치마크 결과, 순수 JS 기반 v3 대비 **최대 10배의 속도 향상**을 보이며 Mixtral 등 MoE 아키텍처를 네이티브 지원합니다.
- **WebLLM (MLC AI)**: Main + Agent + WebLLM Worker의 **3W Thread Model**을 통해 추론 중에도 60fps UI를 유지합니다.

- **Speculative Decoding**: 브라우저 엔진 수준에서 추측적 디코딩을 통합하여 모바일 브라우저 체감 속도를 2배 이상 향상시켰습니다.
- **Chrome 내장 AI (Gemini Nano)**: Prompt API(`window.ai`)를 통해 별도의 모델 다운로드 없이 OS 수준에서 제공되는 모델을 표준화된 방식으로 활용 가능합니다.

## 3. 2026 SOTA 모델 및 성능 지표

| 체급 | 대표 모델 | 성능 (t/s) | 특이사항 |

| Tiny | SmolLM2-360M | 100+ | 실시간 번역/요약 |
| Small | **Llama 4 Scout** | 30-50 | **Sweet Spot**. 10M 컨텍스트, RTX 4070(1M context) 시 4.1 t/s |

- **Llama 4 시리즈**: Scout(17B MoE)는 10M 컨텍스트 윈도우를 지원. Groq 가속 시 2,600 t/s 및 $0.08/1M 토큰(입력) 수준의 경제성 확보.

## 4. 최신 최적화 기법

- **Speculative Speculative Decoding (SSD)**: **Saguaro 알고리즘**(arXiv:2603.03251) 도입. 비동기 병렬 검증 방식으로 기존 대비 최대 5배 속도 향상.
- **KIV (K-vector Indexing)**: 2026년 4월 발표. 컨텍스트 길이에 관계없이 VRAM 사용량을 약 12MB로 일정하게 유지하여 소비자용 GPU에서 초장문 처리 가능.
- **SolidAttention**: SSD(저장장치) 오프로딩을 통해 저사양 기기에서 대형 모델 구동 지원.
- **WebMCP**: 모델이 브라우저 로컬 데이터(파일, 센서)에 안전하게 접근하는 표준 프로토콜.
